# 多人联机开发方案

> 类银河恶魔城 Unity 2D 动作RPG — 毕设项目  
> **网络方案**：自研 LiteNetLib（源码编译）+ 自研 Unity 网络层（游戏对象同步）  
> **联机模式**：Listen Server（主机模式），纯单机模式保留  
> **传输切换**：自研 LiteNetLib（局域网/直连）↔ Steamworks（大厅/P2P）  
> **时间预算**：5 个月以上  
> **当前进度**：阶段一 ✅ | 阶段二 ✅ | 聊天系统 ✅ | 阶段三（设计中）

## 二、关键设计决策

| 序号 | 决策 | 选择 | 原因 |
|------|------|------|------|
| 1 | 传输抽象 | `IGameTransport` 接口 | 可切换 LiteNetLib ↔ Steamworks |
| 2 | RPC 风格 | MessageRouter 注册分发，手动序列化 | 零反射、零 GC、可追踪 |
| 3 | 网络库方式 | **源码直接编译**（去 DLL） | 避免版本不一致 |
| 4 | 执行权限 | `IsAuthoritative` 单一守卫 | 服务端跑逻辑，客户端只渲染 |
| 5 | 输入管线 | 统一 `ApplyInput(data)`，不区分来源 | 本地键盘和网络输入走同一条路 |
| 6 | 实体开关 | 非权威实体 `Entity.enabled = false` | Unity 不调用 Update，彻底停掉 |
| 7 | 单例策略 | `IsSpawningRemote` 标志 + component.Get | Prefab 实例化时保护 Instance |
| 8 | 消息分发 | MessageRouter 注册模式 | 各系统不互相抢消息 |
| 9 | 位置同步 | 服务端快照 + 客户端 NetworkTransform 插值 | 平滑不抖动 |
| 10 | HitStop 顿帧 | 联机模式攻击者本地执行 | 不碰 Time.timeScale，手感保留 |
| 11 | 伤害计算 | 服务端执行，广播 DamageEvent | 单一真理源 |
| 12 | 客户端预测 | 不实现 | LAN 延迟 <5ms 无感知 |
| 13 | 断线重连 | 不实现 | 显示"主机已断开"即可 |
| 14 | 主机迁移 | 不实现 | 主机断开即解散 |

## 五、阶段三：游戏逻辑网络化 — 详细设计

---

### 5.1 核心设计原则

**一句话概括**：给房子加一个门禁。没权限的人进不去，进去的人不用知道外面有网络。

```
单机模式                              联机模式
────────                              ────────
NetworkManager == null                NetworkManager 存在
  ↓                                     ↓
IsAuthoritative = true               IsAuthoritative = IsServer
  ↓                                     ↓
所有逻辑照常跑                        服务端跑所有逻辑，客户端只渲染
```

**与 GDD 初版的核心区别**：初版是"在 15 个文件里各处打补丁（isLocalPlayer/isRemotePlayer/IsMine + 到处加 if 守卫）"，新方案是"一处控制 + 一条管线 + 零侵入"。

---

### 5.2 完整的"什么跑在哪"

#### 游戏逻辑 — 服务端权威（SERVER ONLY）

| 系统 | SERVER | CLIENT | 原因 |
|------|--------|--------|------|
| **Player 状态机** | ✅ 完整跑 | ❌ | 多玩家状态一致，Server 是唯一真理源 |
| **Enemy 状态机 AI** | ✅ 完整跑 | ❌ | 避免两个客户端敌人行为不同 |
| **Physics2D 碰撞检测** | ✅ 执行 | ❌ | 攻击命中判定、地面检测只有一份结果 |
| **Entity_Combat.PerformAttack()** | ✅ 执行 | ❌ | 物理检测、伤害计算、元素效果在服务端 |
| **Entity_Health.TakeDamage()** | ✅ 计算 | ❌ | 护甲减免、元素抗性、暴击在服务端算，客户端等 DamageEvent |
| **Random (暴击/闪避/掉落)** | ✅ 服务端种子 | ❌ | 两个客户端各 roll 一次结果不同 |
| **Skill_Base.TryUseSkill()** | ✅ 验证+执行 | ❌ | 冷却/消耗/等级验证在服务端 |
| **技能效果（弹幕/领域）** | ✅ 执行 | ❌ | 弹幕生成位置、伤害判定在服务端 |
| **Entity_StatusHandler** | ✅ 执行 | ❌ | Buff/状态效果由服务端应用 |
| **Enemy.Die()** | ✅ 决定 | ❌ | 何时死、掉落什么由服务端判定 |
| **LootDropper / LootManager** | ✅ 决定 | ❌ | 掉落计算用服务端 Random |
| **QuestManager** | ✅ 判定 | ❌ | 杀敌计数、拾取计数由服务端说了算 |
| **ExperienceManager / PlayerLevelManager** | ✅ 计算 | ❌ | 经验值分配、升级判定在服务端 |
| **背包操作（拾取/丢弃/装备）** | ✅ 验证+执行 | ❌→请求 | 客户端发请求，服务端验证后修改数据 |
| **物品消耗（喝药/卷轴）** | ✅ 执行 | ❌→请求 | 服务端验证物品存在+数量够 → 扣物品 → 加效果 |
| **装备属性生效** | ✅ Entity_Stats | ❌ | 装备加成的属性由服务端 Stats 计算 |

#### 输入采集 — 分场景

| 场景 | 谁采集 | 流向 |
|------|--------|------|
| **单机** | InputCollector 读键盘 | → `Player.ApplyInput(data)` 本地应用 |
| **Host 本地玩家** | InputCollector 读键盘 | → `Player.ApplyInput(data)` 本地直接应用（零延迟） |
| **Host 接收远端输入** | 不采集 | 网络收到 → `Player.ApplyInput(data)` 应用到对应 Player |
| **Client 本地玩家** | InputCollector 读键盘 | → `SendToServer(data, unreliable)` 发服务端（客户端自己不动） |
| **Client 远端玩家** | 不采集 | 等状态同步广播 |

#### 表现层 — 各客户端本地播放

| 系统 | SERVER | CLIENT | 原因 |
|------|--------|--------|------|
| **Transform 移动** | ✅ 物理驱动 | ❌→插值 | 客户端不跑物理，从服务端位置 lerp |
| **Animator 播放** | ✅ 状态机驱动 | ❌→同步 | 客户端不跑状态机，从 animStateHash 同步 |
| **VFX (受击/暴击/元素)** | ✅ 事件触发 | ✅ 事件触发 | 纯视觉表现，DamageEvent 触发各自播放 |
| **音效** | ✅ 事件触发 | ✅ 事件触发 | AudioManager 各自播放，不走网络 |
| **屏幕震动** | ✅ 本地 | ✅ 本地 | 纯手感反馈，各自震各的 |
| **HitStop 顿帧** | ✅ 攻击者本地 | ✅ 攻击者本地 | 谁出手谁顿帧，不影响其他人。手感反馈不涉及公平性 |
| **UI (血条/背包/技能树)** | ✅ 本地数据 | ✅ 本地数据 | UI 读的是本地数据副本，网络事件来更新副本 |
| **角色面向 (Flip)** | ✅ 逻辑决定 | ✅ 状态同步 | PlayerState 中包含 facingRight 标志 |

### 5.3 核心机制：IsAuthoritative

**唯一守卫** — 整个游戏逻辑层只加这一个检查。

```csharp
// Entity.cs
public bool IsAuthoritative
{
    get
    {
        var net = NetworkManager.Instance;
        if (net == null || !net.IsRunning) return true;  // 单机：全有权威
        return net.IsServer;  // 联机：只有服务端有权威
    }
}
```

**关键机制**：非权威实体直接 `Entity.enabled = false`，而不是在 Update() 里 return。

```csharp
// PlayerSpawner / SpawnSystem 在创建非权威实体后：
if (!IsAuthoritative)
    entity.enabled = false;
```

**为什么用 enabled = false 而不是 return？**

```csharp
// ❌ 在 Entity.Update() 里 return
protected virtual void Update()
{
    if (!IsAuthoritative) return;  // 只退出 Entity.Update()
    stateMachine.UpdateActiveState();
}

// Player.cs
protected override void Update()
{
    base.Update();           // Entity.Update() return 了
    ApplyInput();           // ← 但这行还会执行！C# 的 return 只退出本方法
    UpdateDynamicGravity(); // ← 这行也会执行！
}
```

```csharp
// ✅ enabled = false
// Unity 不再调用 Entity 和所有子类（Player/Enemy）的 Update()、FixedUpdate()、LateUpdate()
// 还对同一个 GameObject 上所有依赖 Entity 的组件有效
```

**单机兼容性**：

```
单机模式：NetworkManager.Instance == null
  → IsAuthoritative = true
  → enabled 保持 true
  → 和现在完全一样，一行改动都不影响
```

### 5.4 统一输入管线

**核心思想**：Player 只暴露一个 `ApplyInput(PlayerInputData)` 方法，不关心输入来源。

```csharp
// Player.cs — 替代原来的 Input() 方法
public void ApplyInput(PlayerInputData data)
{
    if (IsDead) return;  // 死亡不响应输入

    xInput = data.Horizontal;
    yInput = data.Vertical;

    // 标准输入缓冲 — 状态机自然消费（和原来 Input() 完全一致的逻辑）
    if (data.JumpPressed)
    {
        if (isOnGround) inputBuffer.AddJumpBuffer();
        else inputBuffer.AddDoubleJumpBuffer();
    }
    if (data.AttackPressed)  inputBuffer.AddAttackBuffer();
    if (data.DashPressed)    inputBuffer.AddDashBuffer();
    if (data.CounterPressed) inputBuffer.AddCounterAttackBuffer();
    if (data.DomainPressed)  skillManager?.domainExpansion?.TryUseSkill();

    // 技能槽
    if (data.SkillSlotIndex >= 0)
        GetComponent<SkillSlotManager>()?.ProcessInput(data.SkillSlotIndex);
}
```

**InputCollector** — 采集端，挂 Player 同 GameObject：

```csharp
// InputCollector.cs
[DefaultExecutionOrder(-100)]  // 确保在 Entity.Update() 之前执行
public class InputCollector : MonoBehaviour
{
    private Player player;
    private bool isActive;

    void Awake() { player = GetComponent<Player>(); }
    void OnEnable() { isActive = true; }   // 只有 IsOwner 的 Player 才会被 PlayerSpawner 激活

    void Update()
    {
        if (!isActive) return;

        var data = new PlayerInputData
        {
            Horizontal = GameInput.Horizontal,
            JumpPressed = GameInput.GetKeyDown(GameInput.Action.Jump),
            DashPressed = GameInput.GetKeyDown(GameInput.Action.Dash),
            AttackPressed = GameInput.GetKeyDown(GameInput.Action.Attack),
            CounterPressed = GameInput.GetKeyDown(GameInput.Action.CounterAttack),
            DomainPressed = GameInput.GetKeyDown(GameInput.Action.DomainExpansion),
            SkillSlotIndex = GetSkillSlotInput(),
        };

        if (IsHost)
            player.ApplyInput(data);       // Host 本地直接应用
        else if (IsPureClient)
            SendToServer(data);            // 纯 Client 发服务端
    }

    bool IsHost => Net != null && Net.IsHost;
    bool IsPureClient => Net != null && Net.IsClient && !Net.IsServer;
}
```

**三模式统一路径**：

```
单机： 键盘 → InputCollector → ApplyInput() → inputBuffer → 状态机
Host： 键盘 → InputCollector → ApplyInput() → inputBuffer → 状态机（本地）
       网络 → PlayerSpawner  → ApplyInput() → inputBuffer → 状态机（远端）
Client：键盘 → InputCollector → SendToServer() → 服务端 → 状态机 → 广播位置
       网络 → NetworkTransform 插值渲染
```

### 5.5 单例处理策略

**问题**：项目有 17+ 个单例，`Instantiate(playerPrefab)` 时 Awake 会跑，可能覆盖 `Instance`。

**方案**：保留 `IsSpawningRemote` 静态标志（经可行性复查确认必要）。

```csharp
// PlayerSpawner.cs
public class PlayerSpawner : MonoBehaviour
{
    public static bool IsSpawningRemote { get; private set; }

    public GameObject SpawnRemotePlayer(int clientId, Vector3 position)
    {
        IsSpawningRemote = true;
        GameObject instance = Instantiate(playerPrefab, position, Quaternion.identity);
        IsSpawningRemote = false;
        // ...
        return instance;
    }
}
```

**每个需要保护的单例 Awake() 加一行**：

```csharp
void Awake()
{
    if (PlayerSpawner.IsSpawningRemote) return;  // ← 就这一行
    // ... 原有 Instance 逻辑不变
}
```

**需要保护的清单**：

| 单例 | 文件 | 优先级 |
|------|------|--------|
| Player_SkillManager | Player_SkillManager.cs | 🔴 必须 |
| SkillSlotManager | SkillSlotManager.cs | 🔴 必须 |
| PlayerLevelManager | PlayerLevelManager.cs | 🔴 必须 |
| AttributePointManager | AttributePointManager.cs | 🔴 必须 |
| ExperienceManager | ExperienceManager.cs | 🔴 必须 |
| PassiveSkillManager | PassiveSkillManager.cs | 🟡 应该 |
| SkillDataManager | SkillDataManager.cs | 🟢 可选（只读数据） |
| SkillPointManager | SkillPointManager.cs | 🟡 应该 |
| QuestManager | QuestManager.cs | 🟡 应该（任务进度按玩家独立） |

**`SkillDataManager` 不需要保护** — 它是只读数据（从 ScriptableObject 加载），多实例共享安全。

### 5.6 消息协议

#### 消息 ID 分配

```
  0- 99  系统消息（连接/心跳/生成/销毁/分配ID）
100-149  RPC 封装（备用）
150-199  实体状态同步
200-249  聊天/社交（200=聊天）
300-349  玩家输入/状态
350-399  战斗消息
400-449  技能消息
450-499  物品/背包/任务
```

#### 消息结构

**MSG_ASSIGN_ID (1)** — Server → Client，可靠，连接后首条
```
[0-3] msgId=1  [4-7] assignedClientId (int32)
```

**MSG_PLAYER_INPUT (300)** — Client → Server，每帧，不可靠（14B body）
```
[0-3] tick (uint32)    [4-7] horizontal (float32)    [8-11] vertical (float32)
[12]  flags (uint8)    bit0=jump bit1=dash bit2=attack bit3=counter bit4=domain
[13]  skillSlot (int8) -1=无 0-4=槽位
```

**MSG_PLAYER_STATE (301)** — Server → All Clients，~15Hz，不可靠（29B body）
```
[0-3] clientId (int32)  [4-7] posX (float32)    [8-11] posY (float32)
[12-15] velX (float32)  [16-19] velY (float32)   [20] flags (uint8)
bit0=facingRight bit1=isOnGround bit2=isDead
[21-24] animStateHash (int32)  [25-28] hpPercent (float32)
```

**MSG_DAMAGE_EVENT (350)** — Server → All Clients，可靠（33B body）
```
[0-3] targetNetId (uint32)   [4-7] dealerNetId (uint32)
[8-11] physicalDamage (float32)  [12-15] elementalDamage (float32)
[16] elementType (uint8)  [17] flags: bit0=isCrit bit1=isKill
[18-21] knockbackX (float32)  [22-25] knockbackY (float32)
[26-29] sourceTick (uint32)  [30-32] reserved
```

**MSG_ENEMY_STATE (360)** — Server → All Clients，~10Hz，不可靠（22B body）
```
[0-3] netId (uint32)  [4-7] posX  [8-11] posY
[12-15] velX  [16-19] velY  [20] stateId (0-5)  [21] hpPercent×255
```

**MSG_SKILL_REQUEST (400)** — Client → Server，可靠（4B body）
```
[0-3] slotIndex (int32)
```

**MSG_SKILL_EVENT (401)** — Server → All Clients，可靠（20B body）
```
[0-3] casterNetId (uint32)  [4-7] skillType (int32)
[8-11] targetPosX  [12-15] targetPosY  [16-19] facingDir (int32)
```

#### 传输可靠性选择

| 消息 | 可靠/不可靠 | 原因 |
|------|-----------|------|
| MSG_PLAYER_INPUT | 不可靠 | 丢一帧无所谓，下一帧 16ms 到 |
| MSG_PLAYER_STATE | 不可靠 | 插值平滑丢失帧 |
| MSG_DAMAGE_EVENT | **可靠** | 少一个扣血事件 = 血条不一致 |
| MSG_SKILL_REQUEST | **可靠** | 技能释放不能丢 |
| MSG_SKILL_EVENT | **可靠** | 少一个技能特效 = 视觉不一致 |
| MSG_ENEMY_STATE | 不可靠 | 高频位置同步 |

#### 带宽估算（4 玩家）

```
输入：14B × 3 远端玩家 × 30Hz = 1260 B/s
状态：33B × 4 玩家 × 15Hz   = 1980 B/s
合计：~3.2 KB/s（LAN 轻松应对）
```

### 5.7 消息路由架构

**问题**：原方案中 ChatManager、SpawnSystem 各自订阅 Transport 事件、各自拆包判断 msgId——容易冲突。

**方案**：MessageRouter 统一入口，各系统注册处理器。

```csharp
// MessageRouter.cs — 统一消息分发
public class MessageRouter : MonoBehaviour
{
    private readonly Dictionary<int, Action<int, byte[]>> _serverHandlers = new();
    private readonly Dictionary<int, Action<byte[]>> _clientHandlers = new();

    void OnEnable()
    {
        var t = NetworkManager.Instance?.Transport;
        if (t == null) return;
        t.OnServerDataReceived += OnServerData;
        t.OnClientDataReceived += OnClientData;
    }

    public void RegisterServer(int msgId, Action<int, byte[]> handler)
        => _serverHandlers[msgId] = handler;
    public void RegisterClient(int msgId, Action<byte[]> handler)
        => _clientHandlers[msgId] = handler;

    void OnServerData(int clientId, byte[] data)
    {
        var (msgId, body) = NetUtil.UnpackMessage(data);
        if (_serverHandlers.TryGetValue(msgId, out var h)) h(clientId, body);
    }
    void OnClientData(byte[] data)
    {
        var (msgId, body) = NetUtil.UnpackMessage(data);
        if (_clientHandlers.TryGetValue(msgId, out var h)) h(body);
    }
}
```

**各系统注册**（在各自的 Init/Start 中）：

```csharp
// 服务端处理器
router.RegisterServer(MsgId.PlayerInput, (cid, body) => OnPlayerInput(cid, body));
router.RegisterServer(MsgId.Chat,        (cid, body) => OnChatMessage(cid, body));
router.RegisterServer(MsgId.SkillRequest,(cid, body) => OnSkillRequest(cid, body));

// 客户端处理器
router.RegisterClient(MsgId.PlayerState,  body => OnPlayerState(body));
router.RegisterClient(MsgId.DamageEvent,  body => OnDamageEvent(body));
router.RegisterClient(MsgId.SkillEvent,   body => OnSkillEvent(body));
router.RegisterClient(MsgId.EnemyState,   body => OnEnemyState(body));
router.RegisterClient(MsgId.Chat,         body => OnChatMessage(body));
```

### 5.8 玩家生成流程（PlayerSpawner）

```
服务端（Host）：
  1. Host 启动 → RegisterHostPlayer(场景中已有的 Player)
     → playerObj.GetComponent<Entity>().enabled = true（本地 Player 有权威）
     → 广播 MSG_SPAWN 给所有已有客户端
  2. 远端客户端连入
     → IsSpawningRemote = true
     → Instantiate(playerPrefab) 生成远端 Player 实例
     → IsSpawningRemote = false
     → Entity.enabled = true（服务端有权威，跑完整状态机）
     → player.isLocalPlayer = false（UI 层感知用）
     → 广播 MSG_SPAWN 给所有客户端
  3. 客户端断线
     → SpawnSystem.Despawn(netObj)
     → 广播 MSG_DESPAWN 给剩余客户端

远端客户端：
  1. 收到 MSG_ASSIGN_ID → 知道自己的 clientId
  2. 收到 MSG_SPAWN
     → 如果 ownerClientId == 我的clientId：
         InputCollector.enabled = true（开始采集输入发送）
         Entity.enabled = false（客户端不跑逻辑，等状态同步）
       → 如果 ownerClientId != 我的clientId：
         InputCollector.enabled = false
         Entity.enabled = false
         → 添加 NetworkTransform 组件，等待状态同步插值
  3. 收到 MSG_PLAYER_STATE
     → 如果 clientId == 我的：跳过（我的位置由 InputCollector 发送给服务端决定）
     → 如果 clientId != 我的：NetworkTransform.ApplyServerState(pos, vel, facing)
```

### 5.9 位置同步（NetworkTransform + SyncManager）

**NetworkTransform** — 挂远程实体，平滑插值：

```csharp
public class NetworkTransform : NetworkBehaviour
{
    [SerializeField] float lerpSpeed = 15f;
    private Vector3 targetPos;
    private Vector3 targetVel;
    private bool hasTarget;

    void Update()
    {
        if (IsOwner || !hasTarget) return;

        // 距离过大时瞬移（防传送卡顿）
        float dist = Vector3.Distance(transform.position, targetPos);
        if (dist > 5f) transform.position = targetPos;
        else transform.position = Vector3.Lerp(transform.position, targetPos, lerpSpeed * Time.deltaTime);
    }

    public void ApplyServerState(Vector3 pos, Vector3 vel, bool facingRight)
    {
        targetPos = pos;
        targetVel = vel;
        hasTarget = true;
        // 面向同步
        Entity e = GetComponent<Entity>();
        if (e != null && (e.facingDir > 0) != facingRight)
            e.Flip();
    }
}
```

**SyncManager** — 服务端协程定时广播：

```csharp
public class SyncManager : MonoBehaviour
{
    [SerializeField] float playerSyncInterval = 0.067f;  // ~15Hz
    [SerializeField] float enemySyncInterval = 0.1f;     // ~10Hz

    IEnumerator Start()
    {
        var wait = new WaitForSeconds(playerSyncInterval);
        while (true)
        {
            yield return wait;
            if (Net.IsServer) BroadcastAllPlayerStates();
        }
    }

    void BroadcastAllPlayerStates()
    {
        foreach (var p in playerSpawner.GetAllPlayers())
        {
            var state = PlayerStateData.Create(/* ... */);
            Net.Broadcast(NetUtil.PackMessage(MsgId.PlayerState, state.Serialize()), false);
        }
    }
}
```

### 5.10 战斗网络化

**DamageEvent 流程**：

```
服务端：
  Entity_Combat.PerformAttack()
    → Physics2D.OverlapCircleAll()  // 只有服务端做物理检测
    → Entity_Health.TakeDamage()    // 只有服务端计算伤害
    → 打包 DamageEventData
    → Net.Broadcast(packet, reliable: true)  // 可靠传输

所有客户端收到 DamageEvent：
  → 找到 targetNetId 对应的 Entity
  → Entity_Health.ReduceHP()          // 更新血条（表现层）
  → Entity_VFX.PlayOnDamageVfx()      // 播放特效
  → AudioManager.PlayHitSfx()         // 播放音效
  → 如果 isKill → Entity.EntityDead() // 播放死亡动画
  → 如果 knockback → Entity.ReciveKnockback()  // 执行击退
```

**关键守卫**：`Entity_Combat.PerformAttack()` 不需要加 `if (!IsServer)`——因为非权威实体 `Entity.enabled = false`，Update() 根本不跑，PerformAttack() 永远不会被客户端调用。

**Entity_Health.TakeDamage() 不需要守卫**——同上，enabled=false 让客户端不跑 Update，但 `TakeDamage()` 是被 DamageEvent 手动调用的（表现层），不需要网络守卫。

### 5.11 技能系统网络化

```
客户端按技能键 → InputCollector 采集（skillSlotIndex = 0-4）
  → 如果是纯 Client：SendToServer(MSG_SKILL_REQUEST) 发服务端
  → 如果是 Host：Player.ApplyInput() 直接消费 → SkillSlotManager.ProcessInput()

服务端收到 MSG_SKILL_REQUEST：
  → 找到对应 Player 的 SkillSlotManager
  → TryUseSkillInSlot(slotIndex)  // 服务端验证冷却/消耗/等级
    → 验证通过 → 执行技能效果
    → Broadcast(MSG_SKILL_EVENT)   // 通知所有客户端播放表现

客户端收到 MSG_SKILL_EVENT：
  → 找到 casterNetId 对应的 Player
  → 播放技能动画/特效/音效
  → 如果生成弹幕 → 等 SpawnSystem 的 MSG_SPAWN 消息
```

### 5.12 物品/背包/任务/经验网络化

**通用模式**：客户端发请求 → 服务端验证 → 广播结果。

| 操作 | 客户端发送 | 服务端处理 | 广播消息 |

## 六、线程安全设计

```
ListenerLoop (后台线程)                    NetworkClient.ReceiveLoop (后台线程)
  ├─ ConcurrentDictionary 操作 ← 安全       ├─ ConcurrentQueue.Enqueue ← 安全
  ├─ ConcurrentQueue.Enqueue ← 安全          └─ (数据排队等待主线程)
  └─ (数据排队等待主线程)                           ↓
        ↓                                Update() (主线程)
  Update() (主线程)                          ├─ clientReceiveQueue 出队
  ├─ serverReceiveQueue 出队                 ├─ OnClientDataReceived(主线程)
  │  └─ OnServerDataReceived(主线程)         └─ MessageRouter 分发
  ├─ serverEventQueue 出队                   └─ UI_Chat.AddMessage → Instantiate
  │  └─ OnServerClientConnected(主线程)
  └─ SyncManager 状态广播
```

**规则**：所有 `OnXxxReceived` / `OnXxxConnected` 事件都在主线程触发，事件处理函数可以直接调用 Unity API。

## 七、与 TCP 对比

| 功能 | ReliableChannel | TCP | 本项目是否需要 |
|------|----------------|-----|---------------|
| 可靠送达 | ✅ ACK + 重传 | ✅ 内置 | ✅ 必要 |
| 按序到达 | ✅ 乱序缓存 | ✅ 内置 | ✅ 必要 |
| 心跳保活 | ✅ 双向 1Hz | ✅ Keep-Alive | ✅ 必要 |
| 断开检测 | ✅ 10s 超时 | ✅ 内置 | ✅ 必要 |
| 流量控制 | ❌ 不需要 | ✅ 内置 | ❌ 消息量小，撑不爆 |
| 拥塞控制 | ❌ Steam 代劳 | ✅ 内置 | ❌ LAN + Steam 不需要 |
| 自适应超时 | ❌ 固定 200ms | ✅ 动态 RTT | ❌ LAN 固定参数足够 |

**结论**：ReliableChannel 已覆盖 TCP 在本项目的所有必要功能。

## 十、核心原则

### 原则 1：不能破坏单机模式
```csharp
// 所有改变通过 NetworkManager.Instance == null 自然隔离
// IsAuthoritative: null → true（单机一切照旧）
// InputCollector: null → 不走网络分支
// enabled=false: 只在联机客户端触发，单机不触发
```
单机时 `NetworkManager.Instance` 为 `null`，所有新代码路径都不会执行。

### 原则 2：自底向上，每阶段可测试
- 传输层已完成（LiteNetLib 库测试）
- 网络管理层已完成（NetworkManager/聊天）
- Step 1-10 完成即可验证双玩家同屏移动
- 每一步都有可演示的成果

### 原则 3：先用 LAN 模式开发，Steam 最后接入
阶段一到三全部用 `LiteNetTransport` 开发。阶段四才换成 `SteamTransport`。

### 原则 4：源码编译，去 DLL
LiteNetLib 源码直接放在 `Assets/Scripts/LiteNetLib/` 下，由 Unity 编译。

### 原则 5：最小侵入，最大兼容
- 游戏逻辑层只加 `IsAuthoritative` 一个属性（Entity.cs, +5行）
- 零新增字段（复用已有 `NetworkBehaviour.IsOwner`）
- 单例只加一行守卫，Instance 语义不变
