# 阶段三：游戏逻辑网络化 — 设计方案

> 基于项目全部 190 个脚本的完整分析，逐系统设计网络化改造方案

---

## 〇、项目现状速览

### 继承层次

```
MonoBehaviour
├── Entity (IHitStopable)  ← Update() 跑状态机 + 碰撞检测
│   ├── Player             ← Input() 读 GameInput，13 种状态
│   └── Enemy              ← Update() 跑 AI 状态机，6 种状态
├── Entity_Combat          ← PerformAttack() → Physics2D → IDamgable
│   └── Player_Combat      ← 连击索引 / 特殊攻击加成 / 反击 / 追击
├── Entity_Health (IDamgable) ← TakeDamage() 计算护甲/抗性/Random闪避
│   └── Enemy_Health       ← 可眩晕 / 试入战斗状态
```

### 关键数据流（单机）

```
GameInput (静态类)
  ↓
Player.Input() → HandleInputBuffer() → jump/dash/attack/counterAttack 缓冲
  ↓
PlayerState.Update() → 检测 Dash / DomainExpansion 全局输入
  ↓
SkillSlotManager.Update() → Input.GetKeyDown → TryUseSkillInSlot()
  ↓
Player_Combat.PerformAttack() → Physics2D.OverlapCircleAll → IDamgable.TakeDamage()
  ↓
Entity_Health.TakeDamage() → AttackEvaded(Random) → CalculateKnockBack → ReduceHP → Die()
  ↓
Entity_Combat.OnTargetHit() → AudioManager.PlayHitSfx() + HitStopManager.TriggerLocalHitStop()
```

### 联网改造的 5 个核心冲突点

| # | 冲突 | 影响 | 严重度 |
|---|------|------|--------|
| 1 | **`Time.timeScale` 全局修改** — HitStopManager 冻结整个游戏 | 一个玩家挨打，所有玩家画面冻结 | 🔴 致命 |
| 2 | **`Random` 各处使用** — 闪避/暴击/掉落均用客户端 Random | 不同客户端结果不一致 | 🔴 致命 |
| 3 | **`SkillSlotManager` 直接用 `Input.GetKeyDown`** — 绕过 GameInput | 远程玩家输入无法注入 | 🟡 中等 |
| 4 | **17 个单例假设只有一个玩家** — Player_SkillManager.Instance 等 | 第二个玩家无法拥有独立技能 | 🔴 致命 |
| 5 | **`PlayerState.Update()` 内检测全局输入** — Dash/DomainExpansion | 远程玩家的状态机也会读本地键盘 | 🟡 中等 |

## 一、核心架构改造

### 1.1 单例 → 实例化（最关键的改造）

**原则**：不消灭单例，而是在联机模式下绕过单例访问。

```
单机模式（不变）：
  Player_SkillManager.Instance  →  场景中唯一的 Player 身上的组件

联机模式（新增路径）：
  本地玩家：player.skillManager（直接引用，不走 Instance）
  远程玩家：player.skillManager（各自 Player 身上的组件实例）
```

**具体做法**：在 Player 的 `Awake()` 中保存自身组件的直接引用（已做到），所有使用 `Xxx.Instance` 的地方增加判断——先尝试从当前 player 引用获取，找不到再用 Instance。

**影响的单例清单**：

| 单例 | 是否需要改造 | 策略 |
|------|-------------|------|
| Player_SkillManager | ✅ 是 | 每个 Player 持有自己的 skillManager 引用，Instance 仅作 fallback |
| SkillSlotManager | ✅ 是 | 每个 Player 持有自己的 SkillSlotManager，禁用 Instance 模式 |
| SkillDataManager | ❌ 否 | 只读数据，多玩家共享安全 |
| SkillPointManager | ✅ 是 | 每个 Player 独立管理 |
| PassiveSkillManager | ✅ 是 | 每个 Player 独立管理 |
| PlayerLevelManager | ✅ 是 | 每个 Player 独立管理 |
| ExperienceManager | ⚠️ 部分 | 经验倍率计算可共享，但"最后击杀"追踪需按玩家 |
| QuestManager | ⚠️ 部分 | 任务进度按玩家独立，但全局任务状态共享 |
| AudioManager | ❌ 否 | 纯表现层，本地播放即可 |
| HitStopManager | ✅ 是 | **必须改为按对象局部顿帧**（不修改 Time.timeScale） |
| UIManager | ⚠️ 部分 | UI 需知道显示哪个玩家的数据 |

### 1.2 Entity / Player 网络化改造

**改造点 1：`Entity.Update()` 增加网络守卫**

```csharp
// Entity.cs — 修改 Update()
protected virtual void Update()
{
    // 网络模式：远端客户端不跑实体逻辑（等状态同步）
    if (NetworkManager.Instance != null && NetworkManager.Instance.IsClient && !IsServer && !isLocalPlayer)
        return;

    if (stateMachine == null) return;
    stateMachine.UpdateActiveState();
    HandleCollisionDetection();
}
```

**改造点 2：`Player.Update()` — 远程玩家跳过本地输入**

```csharp
// Player.cs — 修改 Update()
protected override void Update()
{
    base.Update();

    // 远程玩家（不由我控制）：不读本地键盘，等网络输入
    if (!isRemotePlayer)
    {
        Input();              // 读 GameInput
        HandleSkillInput();   // 已在 Player.Input() 中调用
    }

    UpdateDynamicGravity();
    UpdateGroundedState();
}
```

**改造点 3：新增 `isLocalPlayer` 和 `isRemotePlayer` 标记**

```csharp
// Entity.cs 新增
public bool isLocalPlayer { get; set; }   // 这个实体是本客户端的本地玩家
public bool isRemotePlayer { get; set; }  // 这个实体是远端客户端的玩家（我不控制它）

// 快速判断
public bool IsMine => isLocalPlayer || (!IsNetworkActive);
// IsNetworkActive: NetworkManager.Instance != null && NetworkManager.Instance.IsRunning
```

**改造点 4：新增网络输入接收方法**

```csharp
// Player.cs 新增
private PlayerInputData pendingNetworkInput;

public void ReceiveNetworkInput(PlayerInputData input)
{
    pendingNetworkInput = input;
}

// 替代 Input() 的网络版本
public void ApplyNetworkInput()
{
    xInput = pendingNetworkInput.horizontal;
    yInput = pendingNetworkInput.vertical;

    // 输入缓冲模拟
    if (pendingNetworkInput.jumpPressed)
    {
        if (isOnGround) inputBuffer.AddJumpBuffer();
        else inputBuffer.AddDoubleJumpBuffer();
    }
    if (pendingNetworkInput.attackPressed)
        inputBuffer.AddAttackBuffer();
    if (pendingNetworkInput.dashPressed)
        inputBuffer.AddDashBuffer();
    if (pendingNetworkInput.counterPressed)
        inputBuffer.AddCounterAttackBuffer();

    // 技能输入
    if (pendingNetworkInput.skillSlotPressed >= 0)
        skillManager?.GetComponent<SkillSlotManager>()?.TryUseSkillInSlot(pendingNetworkInput.skillSlotPressed);
}
```

### 1.3 输入系统改造

**`PlayerState.Update()` 中全局输入检测的问题**：

```csharp
// PlayerState.cs — 当前代码
public override void Update()
{
    base.Update();
    if (GameInput.GetKeyDown(GameInput.Action.Dash) && CanDash())  // ← 远程玩家也会触发
        ...
    if (GameInput.GetKeyDown(GameInput.Action.DomainExpansion) && ...)  // ← 同上
        ...
}
```

**改造方案**：增加本地玩家守卫

```csharp
public override void Update()
{
    base.Update();

    // 只有本地玩家才检测全局输入
    if (!player.isRemotePlayer)
    {
        if (GameInput.GetKeyDown(GameInput.Action.Dash) && CanDash()) { ... }
        if (GameInput.GetKeyDown(GameInput.Action.DomainExpansion) && ...) { ... }
    }
}
```

### 1.4 HitStopManager 改造（关键）

**当前问题**：`HitStopManager.TriggerLocalHitStop()` 内部使用协程 + `Time.timeScale = 0` 冻结全局。

**改造方案**：联机模式下，顿帧改为"仅冻结指定实体"而非全局时间缩放。

```csharp
// HitStopManager 新增联机模式保护
public void TriggerLocalHitStop(GameObject attacker, GameObject target, float duration)
{
    // 单机模式：用 Time.timeScale（保持原有行为）
    if (NetworkManager.Instance == null || !NetworkManager.Instance.IsRunning)
    {
        TriggerLocalHitStop_Original(attacker, target, duration);
        return;
    }

    // 联机模式：只冻结指定实体的动画/速度，不修改 Time.timeScale
    TriggerLocalHitStop_Networked(attacker, target, duration);
}
```

**联机版顿帧**：设置 `Entity.SetAnimationSpeed(0)` + `Entity.SetVelocity(0,0)`，用 `Time.unscaledDeltaTime` 计时恢复，不使用 `Time.timeScale`。

## 二、消息协议设计

### 2.1 消息 ID 分配

| 范围 | 用途 |
|------|------|
| 0-99 | 系统消息（连接/心跳/生成/销毁） |
| 100-149 | RPC 封装 |
| 150-199 | 实体状态同步 |
| 200-249 | 聊天/社交（200=聊天） |
| 300-349 | 玩家输入/状态 |
| 350-399 | 战斗消息 |
| 400-449 | 技能消息 |
| 450-499 | 物品/背包/任务 |

### 2.2 玩家输入消息（MSG_PLAYER_INPUT = 300）

**方向**：Client → Server，每帧，不可靠传输

```
字节布局（共 13 字节）：
  [0-3]    msgId (int32) = 300
  [4-7]    tick (uint32)        — 输入序号，用于丢包检测
  [8-11]   horizontal (float32) — 水平输入 -1~1
  [12]     flags (uint8)        — bit0=jump, bit1=dash, bit2=attack, bit3=counterAttack
  [13]     skillSlot (int8)     — 技能槽位 -1=无, 0-4=槽位索引
```

### 2.3 玩家状态消息（MSG_PLAYER_STATE = 301）

**方向**：Server → All Clients，~15Hz（每 67ms），不可靠传输

```
字节布局（共 29 字节）：
  [0-3]    msgId (int32) = 301
  [4-7]    clientId (int32)      — 哪个玩家
  [8-11]   posX (float32)
  [12-15]  posY (float32)
  [16-19]  velX (float32)
  [20-23]  velY (float32)
  [24]     flags (uint8)         — bit0=facingRight, bit1=isOnGround, bit2=isDead
  [25-28]  animStateHash (int32) — 当前 Animator 状态的 hash
```

### 2.4 战斗消息

**DamageEvent (MSG_DAMAGE_EVENT = 350)**

方向：Server → All Clients，可靠传输

```
字节布局（共 33 字节）：
  [0-3]   msgId (int32) = 350
  [4-7]   targetNetId (uint32)    — 被打的实体
  [8-11]  dealerNetId (uint32)    — 攻击者实体
  [12-15] physicalDamage (float32)
  [16-19] elementalDamage (float32)
  [20]    elementType (uint8)     — 0=None,1=Fire,2=Ice,3=Lightning
  [21]    isCrit (uint8)
  [22-29] knockbackX, knockbackY (float32, float32)
  [30]    isKill (uint8)          — 是否击杀
```

**EnemyStateUpdate (MSG_ENEMY_STATE = 360)**

方向：Server → All Clients，~10Hz，不可靠传输

```
字节布局（共 25 字节）：
  [0-3]   msgId = 360
  [4-7]   netId (uint32)
  [8-11]  posX (float32)
  [12-15] posY (float32)
  [16-19] velX (float32)
  [20-23] velY (float32)
  [24]    stateId (uint8) — 0=Idle,1=Move,2=Attack,3=Battle,4=Dead,5=Stunned
```

### 2.5 技能消息

**SkillCastRequest (MSG_SKILL_REQUEST = 400)**

方向：Client → Server，可靠传输

```
  [0-3]   msgId = 400
  [4-7]   slotIndex (int32)  — 0-4
```

**SkillCastEvent (MSG_SKILL_EVENT = 401)**

方向：Server → All Clients，可靠传输

```
  [0-3]   msgId = 401
  [4-7]   casterNetId (uint32)
  [8-11]  skillType (int32)
  [12-15] targetPosX (float32)
  [16-19] targetPosY (float32)
  [20-23] facingDir (int32)
```

## 三、子系统改造详情

### 3.1 玩家生成流程（PlayerSpawner）

这是第一个里程碑的核心组件。

```
服务端（Host）：
  1. 自己连入 → 场景中现有 Player 标记为 hostPlayer (isLocalPlayer=true)
  2. 远端客户端连入 → 从 Player 预制体 Instantiate，标记为 remotePlayerOnServer
     ↓ 
     分配 ownerClientId = 该客户端 ID
     ↓
     广播 SpawnPlayer 给所有客户端

远端客户端：
  收到 SpawnPlayer → 实例化 Player 预制体
     ↓
     如果 ownerClientId == 我的ID → isLocalPlayer=true（这是我控制的角色）
     否则 → isRemotePlayer=true（这是别人的角色，等状态同步）
```

### 3.2 输入同步流程（帧循环）

```
远端客户端（每帧）：
  Player.Input() → 读 GameInput → 打包 PlayerInputData
    → Net.SendToServer(packet, reliable=false)  // 不可靠，每帧都发

服务端（收到远端输入）：
  OnServerDataReceived(clientId, MSG_PLAYER_INPUT)
    → 找到对应 Player（通过 clientId → player 映射）
    → player.ReceiveNetworkInput(input)          // 写入 pendingNetworkInput
    → player.Update() 时 ApplyNetworkInput()     // 状态机读取

服务端（每 ~67ms）：
  收集所有 Player 的当前状态
    → 打包 PlayerStateData[clientId]
    → Broadcast(packet, reliable=false)

远端客户端（收到状态）：
  OnClientDataReceived(MSG_PLAYER_STATE)
    → 遍历所有 PlayerStateData
    → 更新对应 remotePlayer 的 targetPosition/targetVelocity/animState
    → 在 Update() 中插值渲染
```

### 3.3 战斗系统网络化

**改造要点**：

1. `Entity_Combat.PerformAttack()` → 只在服务端执行（加 `if (!IsServer) return` 守卫）
2. `Entity_Health.TakeDamage()` → 只在服务端执行计算，客户端只负责表现
3. 攻击检测（`Physics2D.OverlapCircleAll`）→ 服务端执行
4. 伤害计算（暴击、护甲、元素抗性）→ 服务端执行（`Random` 使用服务端种子）
5. `AttackEvaded()` 中的 `Random` → 只在服务端判定，结果广播给客户端
6. 击退 → 服务端计算方向和力度，放在 DamageEvent 中广播

**客户端收到 DamageEvent 后**：
- 更新血条（Entity_Health.OnHealthUpdate）
- 播放受击动画
- 播放受击 VFX（Entity_VFX.PlayOnDamageVfx）
- 执行击退（Entity.ReciveKnockback）
- 如果 isKill → 播放死亡动画
- **不需要重新计算伤害**

### 3.4 敌人 AI 服务端驱动

**改造要点**：

```csharp
// Enemy.cs — Update() 改造
protected override void Update()
{
    // 只有服务端跑 AI
    if (IsServer)
    {
        base.Update();  // stateMachine + collision detection
        // 定期广播状态给客户端
        if (Time.time - lastEnemySync >= enemySyncInterval)
            BroadcastEnemyState();
    }
    // 客户端不跑 AI，从接收的状态更新中驱动表现
}
```

**客户端敌人表现**：
- 位置：从 `EnemyStateUpdate` 插值
- 动画：`anim.Play(stateId对应的动画名)`
- 受击：由 `DamageEvent` 驱动
- 死亡：由 `DamageEvent.isKill` 驱动

### 3.5 技能系统网络化

**核心问题**：`SkillSlotManager` 用 `Input.GetKeyDown` 直接读键盘，绕过 `GameInput`。

**改造方案**：

1. `SkillSlotManager.Update()` 增加 `isRemotePlayer` 守卫
2. 技能释放流程改为：

```
客户端：按技能键 → SkillSlotManager.TryUseSkillInSlot()
  → Skill_Base.TryUseSkill()
    → if (IsClient && !IsServer):
        SendToServer(MSG_SKILL_REQUEST, slotIndex)  // 请求服务端释放
        return  // 不等结果，客户端乐观播放？（或等待确认）
    → if (IsServer):
        验证冷却/消耗 → 执行技能效果 → Broadcast(MSG_SKILL_EVENT)

服务端收到 MSG_SKILL_REQUEST：
  → 找到对应 Player 的 SkillSlotManager
  → TryUseSkillInSlot(slotIndex) — 服务端执行完整流程
  → 自动广播 SkillCastEvent
```

3. 技能冷却在服务端维护（防御客户端篡改）

### 3.6 物品/背包/任务系统网络化

**策略**：服务端权威，客户端镜像。

```
背包操作：
  客户端拾取物品 → SendToServer(MSG_PICKUP_ITEM, itemId)
  服务端验证 → 修改服务端背包 → Broadcast(MSG_INVENTORY_UPDATE)
  客户端收到 → 更新本地 UI

装备操作：
  客户端拖拽装备 → SendToServer(MSG_EQUIP, slotIndex, itemId)
  服务端验证 → 修改 Stats → Broadcast(MSG_EQUIP_UPDATE)

任务进度：
  服务端运行 QuestManager（所有进度判定在服务端）
  QuestEvents 事件由服务端发出
  任务状态变更 → Broadcast 给相关客户端
```

**背包存储**：服务端持有每个玩家的 `Inventory_Player` 实例（通过 clientId 索引），客户端只缓存 UI 显示的物品列表。

### 3.7 经验/等级系统网络化

```
服务端：
  Enemy.Die() → ExperienceManager 计算经验值
    → 找到击杀者 clientId
    → PlayerLevelManager[clientId].AddExperience(amount)
    → Broadcast(MSG_EXPERIENCE_GAIN, clientId, amount, newLevel?)

客户端收到：
  → 如果是自己 → 更新 UI（经验条/等级/技能点）
  → 如果是别人 → 可选的提示（"玩家X 升到 Lv.Y"）
```

## 四、数据流总览

### 4.1 帧循环（Listen Server 模式）

```
                    ┌─── Host（服务端 + 本地玩家）───┐
                    │                                 │
  本地玩家输入 ──→ Player.Input() ──→ 状态机 ──→ 物理/战斗
                    │                                 │
  远端客户端输入 ──→ OnServerData ──→ RemotePlayer.Input() ──→ 状态机
                    │                                 │
                    │  ← 每 67ms 广播所有玩家状态 ←    │
                    │  ← 战斗事件发生即广播 ←          │
                    └─────────────────────────────────┘
                                    ↓
                    ┌─── 远端客户端 ──────────────────┐
                    │                                 │
  本地玩家输入 ──→ Player.Input() ──→ 打包发送 ──→ 服务端
                       ↓（乐观预测，可选）
                    本地状态机（轻量，仅表现）
                    │                                 │
  收到状态广播 ──→ 更新 RemotePlayer.transform + anim
  收到战斗事件 ──→ 播放 VFX/SFX/击退
                    └─────────────────────────────────┘
```

### 4.2 Listen Server 角色分工

| 系统 | 服务端(主机) | 远端客户端 |
|------|-------------|-----------|
| 玩家输入 | 读本地 GameInput | 发送输入 → 主机执行 |
| 状态机 | ✅ 跑完整 FSM | ❌ 不跑（等状态同步） |
| 物理/碰撞 | ✅ 服务端计算 | ❌ 不跑 Physics2D |
| 伤害计算 | ✅ 主机负责 | ❌ 不计算 |
| Random 调用 | ✅ 主机种子 | ❌ 只用确定性表现 |
| 敌人 AI | ✅ 主机跑 FSM | ❌ 不跑，等状态同步 |
| 战利品生成 | ✅ 主机 Random | ❌ 等通知 |
| 背包操作 | ✅ 主机验证后修改 | 发请求 → 主机验证 |
| 技能释放 | ✅ 主机验证冷却/消耗 | 发请求 → 主机验证 |
| 任务进度 | ✅ 主机判定 | ❌ 不判定 |
| 经验获得 | ✅ 主机计算 | ❌ 接收通知 |
| **顿帧/TimeScale** | ✅ 改用实体级顿帧 | ✅ 播放顿帧表现 |
| **音频** | ✅ 本地播放 | ✅ 本地播放（随事件触发） |
| **VFX** | ✅ 本地播放 | ✅ 本地播放（随事件触发） |

## 六、可行性分析

### 6.1 技术可行性 ✅

| 方面 | 分析 |
|------|------|
| **网络底层** | LiteNetTransport 已稳定：ReliableChannel（ACK/重传/空洞跳过）、心跳（1Hz）、10s 超时、线程安全队列桥接。所有网络事件在主线程触发，可直接用 Unity API。✅ |
| **传输模式** | 可靠通道用于关键事件（伤害/技能/物品），不可靠通道用于高频状态同步（输入/位置）。ReliableChannel 已覆盖本项目所需的可靠送达+有序+心跳+断开检测。✅ |
| **带宽估算** | 玩家状态：29字节 × 4玩家 × 15Hz = 1740 B/s。玩家输入：13字节 × 3远端玩家 × 60Hz = 2340 B/s。合计 < 5KB/s，对局域网来说极低。✅ |
| **CPU 开销** | 消息序列化均为手动 BitConverter/BlockCopy，零反射、零GC。状态机服务端运行无额外开销。✅ |
| **Unity API 限制** | 已通过线程安全队列解决（所有 Unity API 调用在主线程）。Instantiante/Destroy/Transform/Animator 均可正常使用。✅ |

### 6.2 改造风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 单例拆分遗漏 | 中 | 高 | 建立联机模式测试清单，每个子系统逐一验证 |
| Time.timeScale 遗留 | 中 | 高 | 全局搜索 `Time.timeScale`，逐个替换 |
| 状态机死循环/不同步 | 低 | 高 | 先在 LAN 下 2 人测试所有状态转换 |
| 性能问题（高玩家数） | 低 | 低 | 本游戏 2-4 人联机，带宽/CPU 远未到瓶颈 |
| 单机模式被破坏 | 中 | 致命 | **所有改动用 `if (NetworkManager.IsRunning)` 守卫**，单机时 NetworkManager 为 null 则完全走原路径 |

### 6.3 不可行 / 暂不实现的功能

| 功能 | 原因 | 替代方案 |
|------|------|----------|
| **客户端预测** | 实现复杂，2D 动作游戏预测易出错 | 阶段三不实现，LAN 延迟 <5ms 无明显感觉 |
| **断线重连** | 需要完整状态快照 + Delta 同步 | 显示"主机已断开"，返回主菜单 |
| **主机迁移** | 需要状态完整同步到新主机 | 不实现，主机断开即解散 |
| **Steam P2P NAT 穿透** | Steamworks 代劳，不需要自己实现 | 阶段四用 SteamNetworkingSockets |
| **反作弊** | Listen Server 模式信任主机 | 不实现 |

### 6.4 与现有代码的兼容性

```
单机模式保证：
  NetworkManager.Instance == null
    → Entity.Update() 直接跑 stateMachine（不进入网络守卫）
    → Player.Input() 读 GameInput（不改）
    → Entity_Combat.PerformAttack() 正常执行（不改）
    → HitStopManager 使用 Time.timeScale（不改）
    → 所有单例正常（不改）
    → 整个游戏行为与现在完全一致 ✅

联机模式（Host）：
  NetworkManager.Instance.IsServer == true
  NetworkManager.Instance.IsClient == true
    → 主机玩家的 Player 标记 isLocalPlayer=true，isRemotePlayer=false
    → 远端玩家的 Player（服务器副本）标记 isLocalPlayer=false，isRemotePlayer=true
    → 敌人只在服务端跑 AI

联机模式（Client）：
  NetworkManager.Instance.IsServer == false
  NetworkManager.Instance.IsClient == true
    → 本地玩家的 Player 标记 isLocalPlayer=true，isRemotePlayer=false
    → 发送输入到服务端，不跑完整状态机逻辑
    → 其他玩家的 Player 标记 isRemotePlayer=true
    → 等状态同步来驱动 Transform/Animator
```

## 八、核心设计原则（重申）

### 原则 1：不破坏单机模式
```csharp
if (NetworkManager.Instance != null && NetworkManager.Instance.IsRunning)
    // 联机路径
else
    // 单机路径（原封不动）
```

### 原则 2：最小侵入
- 优先用 `#if` 或条件守卫，不改函数签名
- 新增字段用 `public` 属性（不用序列化），不影响现有 Inspector 配置
- 不在构造函数/静态初始化中做网络操作

### 原则 3：自底向上，每步可验证
- 每一步完成都有可演示的成果
- 每一步完成后都测试单机 + 联机两种模式

### 原则 4：性能意识
- 高频消息用不可靠传输（输入 60Hz、状态 15Hz）
- 低频消息用可靠传输（战斗事件、技能释放）
- 序列化零 GC（手动字节操作）
