## 2. 核心公式（已验证合理，不改）

```
最终值 = (基础值 + Σ固定修饰符) × (1 + Σ百分比修饰符)
```

| 特性 | 说明 |
|------|------|
| 百分比同池相加 | 两个 +10% = ×1.20，非 ×1.21 — 防止连乘爆炸 |
| 护甲减免 | mitigation = armor / (armor + 100)，上限 75% — 天然递减收益 |
| 力量不吃全伤% | GetBasePhyiscalDamage = 物伤值 + 力量×0.5，力量在百分比括号外 |
| HP% 乘所有固定 HP | (基础 + 装备HP + 词缀HP) × (1 + HP%)，活力在括号外 |
| 全伤%独立展开 | 一个"全伤+10%"= 物理/火/冰/雷各 +10% |
| 百分比作用域 | 最终值=(基础+Σ固定)×(1+Σ百分比)。例：护甲100+装备固定10+词缀20% → (100+10)×1.20=132，**非** 100×20%+10。百分比只乘"该属性自身的基础+固定之和"，主属性(力量/活力/智力)间接加成在括号外 |

## 3. 装备稀有度与词缀（方案 B）

**关键设计决策**：稀有度**不放大**词缀数值。

| 机制 | 稀有度作用 |
|------|-----------|
| 装备底材 | 受稀有度倍率影响（1.0/1.5/2.0/2.5/3.0）— 高稀有度底材更强 |
| 词缀数值 | 只看词缀自身 tier 的 min-max，不乘稀有度倍率 |
| 词缀选取 | 稀有度决定可选词缀 tier 上限（普通装只能出普通词缀，传说装能出到传说词缀） |

**理由**：辨识乐趣（传说装可能出 4 个普通词缀，需玩家辨识）+ 数值可预测（+3 就是 +3）+ 平衡可控。

## 6. 词缀数值表（已写入 EquipmentAffixes.csv）

> 数值明细以 `Resources/CSV/EquipmentAffixes.csv`（114 条）为准，此处记录规则。

### 6.1 稀有度调性表（2026-08-01 重构）

**核心设计：稀有度决定词缀池的"味道"**——类型构成按稀有度配置，通过池内数量配比实现。

| 稀有度 | 词缀tier范围 | 允许词缀类型（池构成） | 数值档 |
|--------|-------------|----------------------|--------|
| 普通 | t0-0 | 正面1/2 + 双刃1/4 + 负面1/4 | 最小 |
| 优秀 | t0-1 | 正面2/3 + 双刃1/3 | 较小 |
| 稀有 | t1-2 | **全双刃**（负面温和） | 正面中等/负面中等 |
| 史诗 | t2-3 | 全正面 | 中等 |
| 传说 | t3-4 | 双刃1/2 + 正面1/2 | 较大/最大 |

**词缀类型**（从效果段自动推断 `AffixType`，无额外列）：
- 正面：所有段为正
- 双刃：≥1 正段 + ≥1 负段
- 负面：所有段为负（纯垃圾）

**双刃负面规则**：
- 稀有级：负面**温和**（护甲/闪避，不碰生命/伤害），如 物伤+10~14% / 护甲-6~-3%
- 传说级：负面**最大**（-20%~-10% 级），高风险高回报
- 普通/优秀级：平衡不极端

**比例 = 池内词缀数量实现**（如普通武器前缀 ≈ 4正+2双+2负），生成时池内加权随机。权重：正面5/双刃4/负面2。

**数值方案**：
- 百分比伤害（锚定中期基础值，解决前期倒挂）：稀有全伤 8~12%（武器）/6~9%（饰品）、史诗 12~18%/9~13%、传说 16~25%/12~18%
- **负面一律用百分比**（前后期代价一致）：数值属性负面用百分比，闪避/暴击率等百分制属性可固定
- **主属性翻倍**（饰品有存在感）：普通 3~5、优秀 6~10

### 6.2 保底机制（词缀 tier 范围）

```
装备稀有度(0-4) → 词缀 tier 范围 = [稀有度-1, 稀有度]
普通(0): t0-0   精良(1): t0-1   稀有(2): t1-2   史诗(3): t2-3   传说(4): t3-4
```

每个池×档位 前后缀候选 ≥3（114 条已满足，校验通过）。t2 档同时含双刃（服务稀有装）与正面（服务史诗装），靠类型标签分流。

### 6.3 数据结构与 CSV 格式

- `EquipmentAffixEntry.statModifiers[]`（上限4段），每段 `{statType, min, max, isPercentage}`，负值=负面效果
- CSV 列（**分列格式**，对齐 Equipment.csv 策划风格，固定 4 组×4 列）：
  `affixId,displayName,tier,pool,weight, stat1,stat1_min,stat1_max,stat1_pct, stat2,...stat4`，空组跳过
- 词缀类型 `AffixType`（正面/双刃/负面）从 `statModifiers` **自动推断**（含正含负=双刃，全负=负面），生成器按稀有度调性过滤类型再选
- 负面词缀 UI：词缀名与效果行橙色警示
- **存档**：`AffixSaveData`/`ModifierSaveData` 序列化词缀，读档精确恢复不重新随机

## 7. Legendary 火系 Build 满配示例（方案 B 估算）

> ⚠️ 旧示例：基于旧传说全伤 7~14%（3条~27%）。2026-08-01 调性重构后传说全伤 16~25%，满配数字需按新数值重算，此处仅保留方法论。

假设全传说词缀（全伤 3 条 ~27%），满配底材：

```
物理: (10裸 + 23底材 + 33词缀) × (1 + 0.27) ≈ 84
火伤: (0 + 0 + 15词缀) × 1.27 ≈ 19
总伤/击 ≈ 84 + 19 + 力量加成 ≈ ~110
生命: (100裸 + 77底材 + 60词缀) ≈ 237 × (1 + 0.05HP%) ≈ 250
EHP vs 骷髅: 护甲 ~30 → 减免23% → 每下3.85 → ~65下
```

对照目标（伤害 32-40）：方案 B 下略高，但因词缀数值固定、无稀有度放大，处于可调可控范围——后续通过词缀权重/数值微调即可。

## 8. 策划工作流（CSV 数据驱动）

```
编辑 Equipment.xlsx / EquipmentAffixes.xlsx
  → sync_xlsx_to_csv.ps1 同步为 CSV
  → Unity 菜单导入:
      · 导入词缀CSV → 生成 EquipmentAffixDatabase.asset
      · ItemCSVImporter → 更新装备底材
      · 初始化词缀系统 → 生成精英词缀库
```

**数据源**：
- 装备底材: `Resources/CSV/Equipment.csv`
- 装备词缀: `Resources/CSV/EquipmentAffixes.csv`
- 精英词缀: 代码配置（AffixSpawner.AffixTypeMap + AffixSystemGenerator）
